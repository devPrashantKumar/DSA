How to read an algorithm

01

Loops

One loop over n → O(n). Nested loops multiply: O(n) × O(n) = O(n²).

02

Sequential steps

Add complexities, keep the dominant term: O(n) + O(n²) → O(n²).

03

Conditionals

Take whichever branch — if/else — has the larger complexity.

04

Recursion

Model as a recurrence, e.g. T(n) = 2T(n/2) + O(n), then solve it (Master Theorem, below).

Solving recurrences — Master Theorem

For recurrences of the form T(n) = a·T(n/b) + f(n) — a subproblems of size n/b, plus f(n) work to divide/combine — compare f(n) against nlog_b a.

CaseConditionResultIntuition
1 f(n) grows slower than nlog_b a Θ(nlog_b a) Cost is dominated by the leaves — the sheer number of tiny subproblems
2 f(n) grows at the same rate as nlog_b a Θ(nlog_b a·log n) Cost is spread evenly across all log n levels of the tree
3 f(n) grows faster than nlog_b a Θ(f(n)) Cost is dominated by the root — the combine step drowns out the recursion
MERGE SORT

T(n) = 2T(n/2) + O(n)

a=2, b=2 → nlog₂2=n, matches f(n)=n → Case 2

Θ(n log n)

BINARY SEARCH

T(n) = T(n/2) + O(1)

a=1, b=2 → nlog₂1=1, matches f(n)=1 → Case 2

Θ(log n)

NAIVE MATRIX MULT.

T(n) = 8T(n/2) + O(n²)

a=8, b=2 → nlog₂8=n³, f(n)=n² is slower → Case 1

Θ(n³)

STRASSEN'S ALGORITHM

T(n) = 7T(n/2) + O(n²)

a=7, b=2 → nlog₂7≈n2.81, f(n)=n² is slower → Case 1

Θ(n^2.81)

Doesn't apply when: subproblems have unequal sizes (e.g. T(n)=T(n/3)+T(2n/3)+O(n) — needs a recursion-tree argument), or the recurrence falls in the gap between cases (e.g. f(n)=n/log n — needs the more general Akra–Bazzi method, below).

Beyond Master Theorem — Akra–Bazzi

Handles what Master Theorem can't: unequal subproblem sizes and f(n) sitting in the gap between the three cases. General form: T(x) = g(x) + Σ aᵢ·T(bᵢx + hᵢ(x)) — each recursive branch can shrink by its own fraction bᵢ.

STEP 1

Find p

Solve for the unique real p such that Σ aᵢ·bᵢp = 1

STEP 2

Plug into the formula

T(x) = Θ( xp · (1 + ∫₁ˣ g(u)/up+1 du) ) — the integral checks g(x) against xp, same job as comparing f(n) to nlog_b a in Master Theorem.

UNEQUAL SPLIT

T(n) = T(n/3) + T(2n/3) + O(n)

Solve (1/3)p+(2/3)p=1 → p = 1

Θ(n log n) — same as balanced merge sort

GAP CASE

T(n) = 2T(n/2) + n/log n

2·(1/2)1=1 → p = 1; integral → ln(ln n)

Θ(n log log n)

Practical takeaway: you rarely grind through the integral by hand. The value is recognizing when Master Theorem doesn't apply — unequal splits, or f(n) in the gap between cases — so you don't force-fit it. For unequal-split recurrences, sketching the recursion tree a few levels deep is often faster than invoking Akra–Bazzi formally.

Recursion stacks cost memory. Every call adds a stack frame — depth n means O(n) space even with zero extra data structures.
Time–space tradeoff. Memoizing Fibonacci trades O(1)→O(n) space to cut O(2ⁿ)→O(n) time. Hash maps trade O(n) space to cut O(n²)→O(n) time.
